# DOMP — Directory Organization & Maintenance Protocol

---

## 1. Purpose

Defines the permanent folder structure for the agent's working directory,
the placement rule for every file (existing and future), and the conditions
under which a new folder may be created. This protocol is permanent and
self-enforcing — the agent applies it automatically, not on request.

---

## 2. Mandatory Base Structure
/

├── /scripts/         → all executable scripts (Node.js, .py, .sh, etc.)

├── /instructions/     → AGENTS.md, L1–L5 files, GLOBAL_HUB_SYNC_LOG.md, SEIUP_STATE.md

├── /protocols/        → standalone reference protocol files

├── /backups/          → sliding-window backups (replaces root-level original/)

│   └── /original/     → existing 3-version sliding window system, unchanged

│   └── /source/       → Versioned backups of project source files and deliverables, governed by SFBP (L1). Max 3 versions retained per file.

├── index.html          → stays in root (active deliverable, not infrastructure)

├── gemini project chat → stays in root (active source file, not infrastructure)

└── AGENTS.md            → root copy stays as a pointer file (see Section 5)

This base structure always exists. It is never collapsed or renamed.

---

## 3. File Placement Rule (applies to every file, always)

| File type | Destination |
|---|---|
| Any script (.js, .py, .sh, .ts, etc.) | `/scripts/` |
| AGENTS.md, L1–L5, GLOBAL_HUB_SYNC_LOG.md, SEIUP_STATE.md | `/instructions/` |
| Any backup copy created under IFMP sliding window | `/backups/original/` |
| Active project deliverables (e.g. index.html) | root |
| Active large source files currently being processed (e.g. gemini project chat) | root |
| Anything not matching the above | root, flagged in next SEIUP cycle for manual placement review |

**Apply this rule:**
- Retroactively, once, to every existing file in the directory.
- Permanently, to every file the agent creates or receives from this point forward, at the moment of creation — not in a later cleanup pass.
> [DOMP Amendment — /protocols/ rule, 2026-06-19]: All future protocol files must be written to and remain in `/protocols/`.


---

## 4. New Subfolder Creation — Trigger Condition

Do not create speculative subfolders. A new subfolder under `/scripts/` or
`/instructions/` (e.g. `/scripts/build/`, `/scripts/dedup/`) is only created
when **both** conditions are met:

1. Five or more files of a clearly distinct sub-type already exist in the
   parent folder (e.g. five+ build-related scripts vs. five+ dedup-related
   scripts), **and**
2. That sub-type is expected to keep growing (not a one-off batch).

If only one condition is met, leave the files flat in their parent folder.
This prevents folder sprawl and keeps search depth shallow for the agent.

When a new subfolder is created under this rule, it must be logged to
`GLOBAL_HUB_SYNC_LOG.md` with: subfolder path, trigger files that justified
it, and date.

---

## 5. Root-Level AGENTS.md Pointer File

Because session-start tooling and external references may expect AGENTS.md
at root, keep a minimal pointer file at root:
AGENTS.md (root pointer)
Full instruction set relocated to /instructions/AGENTS.md as of [DATE]

per DOMP. Read /instructions/AGENTS.md for all directives.

The real, authoritative AGENTS.md lives in `/instructions/`. The root copy
is never the one edited, backed up, or treated as source of truth.

Collision Risk: Because the pointer file shares its name with the
real file, all file-read and search operations (grep_search,
view_file, find_file) must be called with absolute paths during
and after DOMP execution. Relative path references to AGENTS.md
are prohibited after the move is complete. The pointer file must
contain at its first line: THIS IS A POINTER FILE — real file is
at /instructions/AGENTS.md — do not edit this file directly.

## 6. Execution Rules

- **Threshold rule applies:** if the one-time retroactive reorganization
  involves moving 20+ files or the directory exceeds 1000 lines of combined
  manifest data, use a deterministic script. Otherwise use native file operations. 
  **Environment-Detected Execution Standard:** Before executing any deterministic script, the Agent MUST identify the active execution environment. Language selection follows from that detection — not from a hardcoded default:
  
  | Environment | Default Language(s) |
  |---|---|
  | Antigravity | PowerShell, then Python |
  | Google AI Studio | Node.js |
  | Unknown / Undetected | Agent MUST stop and ask before proceeding — do not guess |
  
  Detection is mandatory, not optional. If the environment cannot be confirmed from session context or a prior explicit statement by the user this session, the Agent surfaces this as a blocker and asks one precise question: "What is the active execution environment for this session?"
  
  Bulk file moves (relocating existing files, not altering instruction-file content) are permitted via deterministic script regardless of file count. The script-ban in IFMP/AGENTS.md Rule 25 applies only to scripts that write or inject content into instruction files — never to relocating them on disk.
- **IFMP governs all instruction-file moves:** moving AGENTS.md, L1–L5,
  GLOBAL_HUB_SYNC_LOG.md, or SEIUP_STATE.md into `/instructions/` must
  follow IFMP — read before write, sliding-window backup before move,
  explicit authorization confirmed before executing.
- **No deletions during reorg.** This protocol only moves and groups files.
  Any file that appears redundant or duplicate is out of scope here — defer
  to `FILE_DEDUP_PROMPT.md` for that, never delete under DOMP.
- **Validation gate applies:** after the reorg, confirm every file that
  existed pre-move still exists post-move (count and byte-size check). If
  any file is missing or smaller than its pre-move baseline → automatic
  failure, halt, report to user before taking further action.

---

## 7. Execution Sequence

1. Snapshot current directory: full file list with byte sizes.
2. Create base structure (Section 2) if not already present.
3. Apply File Placement Rule (Section 3) to every existing file.
4. Check New Subfolder Creation trigger (Section 4) against the now-grouped
   files; create subfolders only where both conditions are met.
5. Create root-level AGENTS.md pointer file (Section 5).
6. Run validation gate (Section 6).
7. Log summary to GLOBAL_HUB_SYNC_LOG.md: files moved, subfolders created
   (if any), validation result.
8. Report final structure to user in a single structured summary. No prose
   explanation beyond the structure itself.

From this point forward, every new file follows Section 3 automatically at
creation time, with no separate cleanup pass required.

## Amendment — /protocols/ Directory Rule

**A. Mandatory placement**
Every new protocol file created from this point forward must be placed in
`/protocols/` at the moment of creation. No protocol file may be written
to root, `/instructions/`, or any other directory.

**B. Definition of "protocol file"**
A protocol file is any file whose primary content is a named, reusable
operating protocol for the agent — including but not limited to files
following the naming conventions `*_protocol.md`, `*_protocol_prompt.md`,
`*_PROMPT.md` (when the prompt defines a standing protocol), and any file
explicitly designated as a protocol in the Protocol Index.

**C. On adoption of a new protocol (PDPP Stage 5)**
When PDPP Stage 5 integration executes, the physical file for the new
protocol must be written to `/protocols/` before any `AGENTS.md` or L-file
entries are made. If the file is not confirmed present in `/protocols/`,
the integration is not considered complete and must not proceed.

**D. Retroactive scope**
Retroactive scope: This rule applies to all files, past and future.
Upon DOMP execution, any protocol file found outside its mandated
directory — regardless of when it was created — must be immediately
migrated to its correct location. Discovery of a misplaced file is
sufficient trigger for migration. No separate user authorization is
required for individual file moves during a DOMP execution run.

**E. Conflict rule**
If any other protocol, prompt, or instruction references a protocol file
path that does not begin with `/protocols/`, that reference is considered
stale. Flag it at the time of discovery and correct the path in the
referencing document via IFMP before proceeding with any other task.
